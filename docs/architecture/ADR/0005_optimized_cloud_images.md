# ADR 0005 Una imagen optimizada en la nube

18/10/2026. El propietario aclara que R2 debe conservar solo la imagen optimizada, con buena legibilidad y poco espacio. Esta decisión sustituye la política de original remoto de ADR 0004; sus reglas de OCR y conservación local siguen vigentes.

Cada importación conserva el original privado en el móvil y genera una sola representación cloud. El perfil `receipt-webp-v1` corrige orientación, aplana sobre blanco, reduce resolución manteniendo al menos 1000 píxeles en el lado corto cuando el origen lo permite, y codifica WebP con calidad 78–94, probando resolución completa cuando la reducción deteriora el texto. No amplía la imagen. Límite remoto por imagen: 2 MiB y nunca más bytes que el origen. Se comprueba PSNR de luminancia ≥36 dB en una vista común de 1600 px. Se repite OCR y se exige conservar el total, fecha, plazos explícitos y precios de artículos reconocidos. Con PSNR inferior a 39 dB también se exige un 90 % de coincidencia de tokens normalizados, incluidos los numéricos; con mayor fidelidad visual se toleran variaciones del OCR completo. El OCR puede cambiar espacios y puntuación o corregir errores del origen. Son controles heurísticos, no una garantía de lectura humana, exactitud de OCR o decodificación QR/barras. Una entrada que ya es más pequeña puede reutilizar sus bytes. Si no puede generar una copia aceptable, conserva el original y deja la sincronización pendiente; nunca sube una fotografía grande como alternativa silenciosa.

El DTO cloud contiene una única variante OPTIMIZED, hash/tamaño del original como procedencia y hash/tamaño propios de la representación. No sube miniaturas. Los PDF siguen como un único ORIGINAL íntegro: rasterizarlos perdería páginas, texto o firmas. El original de imagen queda en el dispositivo; recuperar desde otra instalación proporciona la copia optimizada. La interfaz y ZIP v3 distinguen estos casos. El manifiesto exporta solo archivos realmente disponibles e indica `original_included` y `originals_missing`.

Room mantiene su esquema v4 y su hash de procedencia para detectar duplicados. Una revisión remota añade la variante optimizada sin eliminar el original local. Las operaciones antiguas se consultan antes de sustituirlas por una nueva clave de idempotencia; nunca se cambia el contenido de una clave ya aceptada. El transporte permite descargar representaciones optimizadas sin exigir un ORIGINAL inexistente.

Para convertir una imagen remota antigua se reserva la copia optimizada y se conserva temporalmente el objeto anterior. El Worker verifica bytes, tamaño y SHA-256 del resultado antes de publicar la revisión canónica y retirar las representaciones remotas anteriores. Una interrupción conserva una lista durable de limpieza. No hay eliminación de originales locales, nuevas tablas, migraciones, planes de pago ni cambios en Supabase. Aplicar este código y convertir objetos reales exige un inventario concreto aprobado; las pruebas locales no constituyen un despliegue.
